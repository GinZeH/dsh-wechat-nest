# 迁移到微巢

微巢（DSH WeChat Nest）的包名与插件标识为 `dsh-wechat-nest`，默认使用独立存储，不会自动读取原插件的登录凭据。

| 项目 | 原版或前期修改版 | 微巢 v0.1.0 |
|---|---|---|
| npm 包及插件标识 | `dsh-wechat` | `dsh-wechat-nest` |
| 设置页 | WeChat | 微巢 |
| 默认存储目录 | `~/.dsh-wechat` | `~/.dsh-wechat-nest` |
| 扫码页 | `/wechat/qr` | `/wechat-nest/qr` |
| 管理 API | `/wechat/api/*` | `/wechat-nest/api/*` |
| Agent 文件/文本推送工具 | `send_wechat` | `wechat_nest_send` |

## 重新扫码使用

1. 停用原插件并退出 DSH，避免同一账号被两个轮询器同时使用。
2. 安装 `dsh-wechat-nest`，重启 DSH。
3. 打开设置 → 微巢，为各个 bot 扫码登录。

旧目录会保留。微巢创建新的账号状态与工作目录。

## 保留现有状态

1. 停用原插件，退出 DSH，并备份旧存储目录。
2. 在新目录尚未初始化时，将旧目录的完整副本放到 `~/.dsh-wechat-nest`。若新目录已有数据，应先备份并人工决定如何迁移，不要直接覆盖。
3. 安装微巢并启动。原单 bot 布局由现有迁移逻辑复制到新目录中的 `bots/main/`；原多 bot 布局保留其注册表与 bot 子目录。
4. 检查每个 bot 的用户、会话、白名单与工作区，确认正常后再恢复使用。

复制存储目录不会移动工作区文件。状态中已有的绝对 `cwd`、管理员分配的目录边界、工作区根目录和排队文件路径会继续指向原位置；如需移动，由管理员在设置页重新分配，并确认旧队列中的文件位置。迁移后不要重新启用原插件轮询同一微信账号。

如果过去在插件装配行显式配置了 `storageDir`，请更新为新位置；显式配置优先于默认目录。保留 `cwd` 等自定义项时应检查目录是否仍为预期位置。

## 自定义接入

- 自建脚本需将 `/wechat/*` 更新为 `/wechat-nest/*`；不提供旧路由别名，以免与原插件冲突。
- 自定义提示词中若写了 `send_wechat`，请更新为 `wechat_nest_send`。微巢只注册新工具名。
- 设置页展开状态使用新 localStorage 命名空间，首次打开会采用默认展开状态。
- 用户数为 1 时也不会放行未归属的桌面会话；文件目录边界继续生效。

目录和会话分开并不限制 Agent 的 shell/read 权限；宿主权限与操作系统沙箱仍需由部署者配置。
